항목현재 값설명
vault_meeting_dir …\옵시디언\회의록 완성된 회의록 .md 파일이 저장될 Obsidian 폴더 경로
whisper_model "medium" STT 모델 크기. small(빠름/낮은 정확도) · medium(균형) · large-v3(최고 정확도, ~3GB)
whisper_device "auto" GPU 사용 여부. auto: GPU 있으면 자동 사용, 없으면 CPU / cpu: 강제 CPU
ollama_model "gemma4:12b" 요약에 사용할 LLM. 빠른 처리가 필요하면 gemma3:latest로 변경
ollama_num_ctx 65536 한 번에 처리할 최대 토큰 수. 한국어 1시간 녹음이면 더 늘릴 수 있음 (131072)
ollama_timeout 5400 (90분) AI 요약 최대 대기 시간(초). 긴 회의나 느린 PC는 늘리세요
save_raw_transcript true 전사(받아쓰기) 원문을 txt로 별도 저장할지 여부. false로 바꾸면 저장 안 함

🛠️ 문제 해결

자주 묻는 질문

오류가 발생하면 아래에서 해결 방법을 찾아보세요.

🔴 "Ollama 호출 실패" 오류가 나요

Ollama 앱이 실행 중이지 않을 때 발생합니다.

# 해결: 아래 명령어로 수동 시작
ollama serve

또는 Windows 시작 메뉴에서 Ollama를 검색해 실행하세요. 트레이(시계 오른쪽)에 Ollama 아이콘이 보이면 정상입니다.

🔴 "Library cublas64_12.dll not found" GPU 오류

CUDA 라이브러리가 PATH에 등록되지 않은 경우입니다. meeting.py가 자동으로 처리하도록 설계되어 있으나, 실패 시 CPU로 자동 전환됩니다. 실제로는 STT가 CPU로 처리되어도 동작합니다(약 3~4배 느림).

강제로 CPU를 사용하려면 config.json에서 "whisper_device": "cpu"로 변경하세요.

🔴 회의록 내용이 중간에 잘려요

녹음이 매우 길거나(1시간 이상) num_ctx가 너무 작을 때 발생합니다.

# config.json 수정
"ollama_num_ctx": 131072  ← 65536에서 두 배로

단, num_ctx가 클수록 요약 시간도 늘어납니다.

🔴 요약이 시간 초과(timeout)로 실패해요

config.json의 ollama_timeout 값을 늘리세요.

"ollama_timeout": 7200  ← 2시간으로 설정
🟡 회의록에 오인식 단어가 계속 나와요

glossary.md에 해당 단어를 추가하세요. 메모장으로 열어 줄을 추가하고 저장하면 됩니다.

# glossary.md에 추가
- `오인식된표현` → **올바른표현** (설명)
🟡 gemma4:12b pull 시 "requires a newer version" 오류

Ollama를 최신 버전으로 업데이트해야 합니다.

# 방법 1: winget (권장)
winget upgrade --id Ollama.Ollama

# 방법 2: 직접 다운로드
# https://ollama.com/download 에서 재설치
🟡 처리 완료됐는데 Obsidian에서 파일이 안 보여요

두 가지를 확인하세요:

1. config.json의 vault_meeting_dir 경로가 실제 Obsidian Vault 폴더와 일치하는지 확인.

2. Obsidian에서 Ctrl+R 또는 좌측 파일 탐색기를 클릭해 새로고침.

🟡 영어 회의도 처리할 수 있나요?

config.json에서 언어와 모델을 변경하세요.

"whisper_language": "en",   ← "ko"에서 변경
"whisper_model":    "medium" ← 동일하게 사용 가능

자동 감지를 원하면 ""(빈 문자열)로 설정하면 됩니다. 단, prompt.md도 영어 지시로 변경해야 영어 회의록이 생성됩니다.

💡 처리 속도를 더 빠르게 하고 싶어요

세 가지 방법이 있습니다:

1. LLM 모델 변경 — gemma4:12b(~17분) → gemma3:latest(~3분)
