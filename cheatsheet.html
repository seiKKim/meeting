뿌리강의 치팅시트

30년 웹 기술의 진화를 4장의 흐름으로 압축한 뿌리강의 핵심 정리. 왜 등장했고, 무엇을 해결했고, 지금 어디로 가는지를 한눈에 잡아 두기 위한 치팅시트입니다.

</>
LECTURE 01 · 1991 ~ 현재
프론트엔드
강의 의도
브라우저 위에서 사용자 경험을 설계하는 기술의 진화 과정을 보여주고, 각 기술이 왜 등장했는지 이해를 돕는다.
핵심 메시지
"모든 기술은 문제를 해결하기 위해 등장했다"
타임라인 (기술 발전사)
1991
HTML
문서 구조 정의 / 정보 공유 목적
1995
JS
브라우저 동적 반응(이벤트/DOM 조작) 처리
1996
CSS
구조와 표현(디자인)의 분리, 유지보수성 향상
2006
jQuery
브라우저 간 비호환성(크로스 브라우징) 문제 해결
2009
Node.js & npm (2010)
JS를 브라우저 밖으로 확장, 라이브러리 조립식 개발 생태계
2013
React
복잡한 상태 관리 해결. "데이터가 바뀌면 화면이 알아서 바뀐다"
—
Webpack / Vite
파일 압축/병합(번들링) 및 최신 문법 변환
—
SPA
페이지 새로고침 없는 앱 같은 부드러운 전환(UX 향상)
—
SSR / Next.js
SPA의 느린 초기 로딩과 SEO(검색엔진 최적화) 문제 해결
핵심 개념
인터넷 vs 웹
인터넷은 물리적 통로(인프라), 웹은 그 위에서 돌아가는 문서 공유 시스템
DOM
브라우저가 HTML을 읽고 만든 내부 지도. JS가 화면을 조작하는 기준
AJAX
페이지 새로고침 없이 백엔드와 데이터를 주고받는 비동기 통신
컴포넌트
재사용 가능한 UI 조각 (레고 블록)
번들링 & Tree Shaking
여러 파일을 하나로 묶고, 안 쓰는 코드를 걸러내어 최적화
하이브리드 렌더링
SSR(서버 렌더링)과 CSR(클라이언트 렌더링)을 상황에 맞게 혼용
HTML CSS JavaScript React NPM SPA SSR
▣
LECTURE 02 · 보이지 않는 곳의 진화
백엔드
강의 의도
보이지 않는 곳에서 데이터를 처리하고 저장하는 엔진의 진화 과정을 통해 백엔드의 역할을 이해시킨다.
핵심 메시지
"어떻게 처리하고 저장할 것인가의 역사"
타임라인 (기술 발전사)
—
정적 웹
있는 파일 그대로 보관 후 전달
—
동적 웹 (CGI/PHP/JSP)
사용자마다 다른 화면을 주기 위해 실시간 HTML 제조
—
DB 도입
파일 저장의 한계 극복, 데이터의 체계적 보관
—
MVC 패턴
코드 복잡도를 줄이기 위해 데이터(M), 화면(V), 로직(C) 분리
2007~
REST API
스마트폰 시대, 앱/웹 모두에 데이터를 공급하는 표준 창구
—
세션/쿠키
무상태(Stateless) HTTP에서 로그인 상태 유지
—
인증/인가/JWT
보안 강화. "누구인가"와 "권한이 있는가"의 분리
—
비동기/동시성
대량 접속 처리 성능 개선
—
캐시(Redis) / CDN
DB 부하 감소 및 응답 속도 극대화
—
트랜잭션(ACID)
결제 등 민감한 작업의 무결성 보장 (전부 성공 or 전부 실패)
—
수평 확장 / 로드밸런서
트래픽 폭주 대응, 서버 대수 증가 및 분산
—
마이크로서비스 (MSA)
서비스 비대화에 따른 배포/장애 국소화를 위한 기능별 분리
—
DevOps / CI/CD
수십 개 서비스의 배포 및 운영 자동화
핵심 개념
서버의 역할 변화
단순 파일 보관소 → 능동적 데이터/HTML 제조 공장
MVC 패턴
Model(데이터), View(화면), Controller(교통정리)
세션 vs 쿠키
세션은 서버 메모리에, 쿠키는 브라우저에 저장하는 번호표
인증 vs 인가
인증(로그인, Who) · 인가(관리자 권한, Can)
REST API MVC JWT Redis 트랜잭션 마이크로서비스 CI/CD
▩
LECTURE 03 · 안전한 보관의 진화
데이터베이스 & 스토리지
강의 의도
안전한 데이터 보관과 대용량 파일 처리의 분리 필요성을 설명하고, DB와 스토리지의 발전 과정을 소개한다.
핵심 메시지
"왜 DB가 생겼고, 왜 스토리지가 분리되었나"
데이터베이스(DB) 역사
—
파일시스템 시대
중복, 불일치, 검색 비효율, 동시 덮어쓰기 문제 발생
1960s
계층형 / 네트워크형
초기 체계화 시도, 구조 변경의 어려움
1970
RDB
Codd의 제안. 데이터를 표(Table)로 저장, JOIN 연결
—
SQL
직관적이고 영어 문장 같은 데이터 조작 언어
—
정규화 & 인덱스
데이터 중복 제거(정규화) 및 고속 검색 색인(인덱스)
2000s
NoSQL
빅데이터 시대, 무한 확장을 위한 유연한 스키마 (MongoDB, Redis)
—
클라우드 DB (Supabase)
관리 자동화 및 개발 속도 중심의 플랫폼화
스토리지 역사
—
서버 직접 저장
디스크 파손 시 유실, 트래픽 감당 불가 문제
2006
Amazon S3
객체 스토리지 패러다임. 서버에서 스토리지 분리
—
CDN / 엣지 서버
전 세계 사용자와 가까운 서버에 복사본 배치, 속도 극대화
핵심 개념
핵심 원칙
파일(이미지/영상)은 스토리지에, DB에는 그 URL(텍스트)만 저장한다.
객체 스토리지 3요소
버킷(창고) · 객체(파일) · 키(파일의 고유 이름)
Presigned URL
특정 시간 동안만 권한을 부여하는 임시 파일 접근 링크
RDB NoSQL SQL Amazon S3 CDN Supabase

LECTURE 04 · 코드가 세상에 도달하는 길
웹서버 & 배포
강의 의도
완성된 코드가 어떻게 전 세계 사용자와 만나게 되는지, 즉 코드가 배포되는 과정을 설명한다.
핵심 메시지
"코드가 완성된 다음, 인터넷에 올라가는 과정"
타임라인 (기술 발전사)
1995
Apache
정적 파일을 안정적으로 던져주는 초기 웹서버 표준
—
WAS
동적 로직(Python, Java 등)을 실행하는 애플리케이션 엔진
2004
Nginx
C10K 문제 해결을 위한 이벤트 기반 웹서버 및 프록시
—
FTP → Git/GitHub
수동 파일 업로드의 오류/덮어쓰기를 버전 관리로 해결
2013
Docker
"내 컴퓨터에선 되는데" 문제 해결, 코드와 환경을 하나로 포장
—
CI/CD
코드 Push 시 테스트부터 배포까지 파이프라인 자동화
—
PaaS (Vercel / Railway)
인프라 설정을 극단적으로 단순화한 클릭형 배포 플랫폼
핵심 개념
웹서버 vs WAS
자판기(정적 파일) vs 바리스타(동적 코드 실행)
리버스 프록시
Nginx가 안내데스크처럼 트래픽을 내부 서버로 분배
도메인/DNS
전화번호부 역할. A레코드(IP) · CNAME(도메인 연결) · MX(메일)
HTTPS
SSL/TLS 암호화 추가 (Let's Encrypt로 무료 자동화 보편화)
로드밸런서 & 오토스케일링
트래픽 폭주 시 부하 분산 및 자동 서버 증설
Nginx Docker CI/CD DNS HTTPS 로드밸런서
